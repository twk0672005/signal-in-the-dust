## 1. 選定方向

**把四區做成由地質與生態關係塑造、能看懂如何探索的完整外星世界。**
沿用 Godot 4.7.2、Compatibility、single-thread Web、既有四區與資產。
改動同時落在空間骨架、材質與生物、玩家目標／互動、網站進入流程；不靠
更多裝飾、厚霧、bloom、影片或假登入掩蓋問題。

| 方向 | 優點與代價 | 決定 |
|---|---|---|
| A：保留所有地形與互動，只調材質、光線、字體和教學 | 改動較小；可改善可讀性，但同一走廊地貌與隱藏互動門檻仍在，難以達到「大幅進步」 | 不作主方案；有價值的局部技巧可採用 |
| B：既有遊戲內重做區域大中形與探索資訊，保留可靠底層 | 地貌／碰撞／接地／Continue 要一起驗，工作較深；能處理構圖重複與遊玩困惑的原因 | **採用**；先形成完整候選，再以實玩修正 |

不重新搭建灰盒、不另開引擎，也不把每個模型／器官變成一輪批准。既有
[環境方向](ENVIRONMENT_UPDATE_PLAN_2026-09-28.md)仍可取用；其舊 STOP、時間窗口、
規劃限定及 ClawTeam 禁令是歷史，不能取代新對話的實作指令。

## 2. 三個最重要問題

### P1：地貌與群落仍像同一條道路換道具

真駕駛圖、側看／回望顯示：大片相似平地與坡面主導畫面；Ember 岩柱重複，
Veil／Pale 群落構圖接近。`world.gd::_base_height_at` 的共用道路側坡、少量
區域波形及模板分布是主要實作線索。問題不等於「樹不夠多」。

優先改輪廓、坡向、前中後景交疊、群落核心／外緣／空隙及跨區過渡，再做
近景表面。保留現有水岸、反射、生物與批量繪製的有效基礎。

### P2：目標仍在算，玩家卻看不到；互動條件又容易消失

`interface.gd` 隱藏距離、活動及生態資訊；一般活動文字會被清空。
`main.gd::_update_survey_readout` 只有手動追蹤邂逅才給地圖目標。
兩次實玩都到達四區，但這不等於玩家能理解主線或完成活動。

E 同時受車速、距離、鏡頭朝向、遮擋及活動狀態限制。一份真旅程三類觀察
成功，另一份 Aeral 經七次小幅接近仍為 `target=none`。這是可重現診斷線索，
不將其草率歸因為單一距離 bug，也不靠放寬測試隱藏問題。

後續聚焦探測用真鍵盤駕到濕地：停車時沒有 E，保持同一車位右鍵向左看後
出現 `ecology`，按 E 成功記錄 Aeral，reload／Continue 保留結果。因此不是
「Aeral 完全不能互動」，而是可見性／姿態／候選選擇與提示缺乏可理解連結；
尚未把朝向、遮擋和生物動態逐項隔離，不能宣稱唯一根因。

### P3：首頁承諾與遊戲第一分鐘斷層，Continue／等待成本難理解

首頁已清楚標概念美術，也沒有帳戶系統。實際開始後缺少清楚的角色、下一個
可感知目標及操作回饋；小而低對比的 HUD 加重問題。Continue 要等引擎驗證
存檔，未知狀態不能假裝已有存檔。入口改善應連同載入、空存檔、失敗恢復及
第一分鐘設計，**不新增假登入或未獲授權的雲端帳戶**。

## 3. 世界與生物的具體改法

| 區域 | 大形／空間 | 中近景與生態 | 玩家如何辨認／探索 |
|---|---|---|---|
| Aurora Shelf | 不對稱風蝕礦台、斷口、崩塌坡及天空缺口 | 迎風磨平、背風積霜、裂縫附著群，减少等距石台列 | 以裂口與礦盆作方向；聲紋／晶簇回應與地形相連 |
| Ember Rift | 錯動斷層、岩肋端部和開闊熱盆，取代錐柱長廊 | 熱源沿裂隙集中，灰積與冷卻區支持不同群落 | 繞過壁端發現 Veyra；冷／暖路線有可見棲地結果 |
| Veil Marsh | 不對稱水盆、根堤、狹長水槽、林緣與開放水面 | 床底→水→濕泥→根群→冠膜連續，密疏由水分和遮蔭決定 | 沿根廊靠岸、停車觀察；Aeral 接近／安靜行為有清楚回饋 |
| Pale Decay | 凹地、剝落沉積台緣、倒根與裸坡 | 分解殘體接地處形成菌床，乾坡留空，成熟度與破損有差異 | 倒根與根脈引導發現 Root Choir，連接結果改變整片局部景觀 |

- 地形高度、渲染、碰撞、放置與生物接地共用同一權威資料。可達區域用真
  幾何；图像遠景只放在合理不可達邊界。保持四區連通與活動開口。
- 任何地形修改都連同 `TERRAIN_REVISION`、舊離路存檔、rover 安全接地處理。
  不以搬回出生點、清檔或停用碰撞掩蓋穿地。
- 生物先改善承重／翼根／甲片／膜面厚薄及受光；表面採生長方向、局部融合、
  磨耗與安靜區，消除整身等距「3D 列印層紋」。保留 IK、翼／冠動態和反應。
- 模板要有地質／生長原因的形態差異，不只縮放旋轉。重用批量和 LOD，但用
  實際鏡位及成本判斷；資產數、節點數或程序噪聲不是畫質指標。
- 先用既有授權資產；新增免費素材記錄來源、授權與 Web 成本。付費生成不在範圍。

## 4. 玩法與第一分鐘

保留自由駕駛、第一／第三人稱及原四區，不強制一條教學走廊。
新玩家在**可操控後的第一分鐘**應理解：自己是探勘者、正在找生命訊號、
先做哪個小動作、成功後世界如何回應。

1. 以一個目前可做的目標和方向呈現，而非恢復整面任務清單。日誌清楚區分
   主調查、區域活動、已觀察生命及可選探索，追蹤行為與 HUD 一致。
2. 校準油門、放油滑行、煞車、倒車和低速轉向；先重現不自然感再改參數或
   方法。現有煞車／倒車功能測試通過，不能據此聲稱手感自然，也不先假定
   轉向一定壞了。新遊戲預設鏡頭依實玩比較決定；保留 V 切換和舊存檔視角。
3. 建立可理解的互動狀態：附近可研究甚麼、需要減速／靠近／轉向／等待甚麼。
   有理由的條件保留；避免逐幀目標跳動、看得到卻永遠猜不到 E。多目標時要有
   明確選擇規則，不用放大到穿牆互動來解決。
4. 讓「發現→觀察→選擇／行動→環境變化→日誌記錄」形成回報。四區活動有
   不同節奏；可重做不自然的既有流程與阻塞條件，但不以新增打卡數量湊時間。
   日誌要承認已發現的物種，而不只列四個可選活動。濕地提供安靜觀察／自然
   恢復的有效路線，不強迫玩家先加速嚇動物才可完成安靜探索。為鍵盤提供
   與觸控 Crawl 相稱的穩定低速控制，服務現有慢速穿行與護送。
5. 用實際鍵盤、鏡頭與觸控重走。測試工具知道座標／門檻，不能代替新玩家
   可理解性。約 30 分鐘內容仍未獲證明，不以慢速駕駛或重複任務冒充。

注意：歷史文件的「4 次測繪＋8 個場記才可初次接觸」不是目前 `interact()`
的實際接觸 gate。不要從舊文檔恢復一套強制打卡；按新體驗決定並同步文案、
規則和測試。成功煞車／倒車／方向符號已有本輪證據，不盲目重寫正確控制。

## 7. 新版本必須通過的驗收

1. **視覺**：同一最終 Web 候選四區正／側／回望、岸邊不利角度及三物種近／中／
   駕駛距離。對照本次 baseline；明確說明輪廓、遮擋、接地與材質改善及不足。
2. **實玩**：首頁→新局→四區真駕駛→主要生物／活動→日誌→pause／真正失焦→
   reload／Continue；含煞車、倒車、雙鏡頭、雙語、觸控。旅程不得 teleport。
3. **入口／保存**：空存檔 Continue、已有進度新局確認、壞／不可寫存檔、載入錯誤
   及重試。不丟舊進度；修改 schema／地形必須有舊檔驗證。
4. **啟動**：冷／暖 UI 回應、真互動時間、所有 raw timer gaps／LongTasks。
   舊 R3 冷約 74.7 秒、最大 gap 約 2.9–3.02 秒，嚴格 ≤2 秒仍 PARTIAL；新候選
   必須重新量測。一次「最後進得去」不是通過。
5. **性能**：Standard1080、Low720，每區至少 30 秒行進／互動，保留全 raw intervals／
   stalls。性能時串行使用 GPU，不截圖、不並跑其他瀏覽器／引擎；不能只報 p95
   或復用舊 PASS。現有 Standard 全區 60 FPS 尚未證明。
6. **產物**：`tools/build-review-candidate.py` 匯出新目錄，bind source／asset／Web
   manifest。測試用 OS 分配埠並先核對 HTML、PCK、WASM 及 immutable release。
7. **接受**：非作者集中覆核；AI 評論只屬 proxy。實機手機、Safari、長時記憶體及
   Nova 最終畫質／市場接受未驗就保留 PARTIAL。根據真缺陷修，不靠固定分數。

測試維護：現有 `habitat_regression.gd` 仍期待舊四批／36 碰撞與舊欄位，不能
無判斷當作現役世界 verdict。優先使用／按當前契約更新
`environment_revision_checks.gd`、`staged_world_checks.gd` 與維護中的 Web harness；
記錄替代覆蓋，不靠刪 assertion 取得綠燈。
